# WordPress Custom Block Plugin

Scaffolds a multi-block WordPress plugin from the bundled template (`template/`). Pattern validated against `column-blocks`.

## Workflow

```
Task Progress:
- [ ] Step 1: Gather plugin info
- [ ] Step 2: Scaffold from template
- [ ] Step 3: Customize first block (optional)
- [ ] Step 4: npm install && npm run build
- [ ] Step 5: Verify build output
```

## Step 1: Gather Plugin Info

Ask the user for:

1. **Plugin slug** (e.g. `my-blocks`) — directory name, text-domain, block namespace
2. **Target directory** — usually `plugins/` in the WordPress project
3. **First block slug** (optional, default `sample-box`)

## Step 2: Scaffold from Template

**Preferred:** run the scaffold script:

```bash
bash ~/skills/wp-custom-block-plugin/scripts/scaffold.sh {plugin-slug} {target-parent-dir} [{first-block-slug}]
```

Example:

```bash
bash ~/skills/wp-custom-block-plugin/scripts/scaffold.sh my-blocks /path/to/plugins hero-box
```

**Manual alternative:** copy `template/` and apply the rename table in [reference.md](reference.md).

The script:

- Copies `template/` to `{target}/{plugin-slug}/`
- Renames `my-blocks.php` → `{plugin-slug}.php`
- Renames `src/my-blocks/` → `src/{plugin-slug}/`
- Replaces `my-blocks` / `my_blocks` identifiers project-wide
- Removes `package-lock.json` (regenerated by `npm install`)

Do **not** copy `node_modules/` or `build/` — those are generated locally.

## Step 3: Customize First Block (Optional)

Edit `src/{plugin-slug}/{block-slug}/` — `block.json`, `edit.js`, `save.js`, styles.

Block file conventions:

| File | Import / role |
|------|----------------|
| `block.json` | `name`: `{plugin-slug}/{block-slug}`, `textdomain`: `{plugin-slug}` |
| `index.js` | `registerBlockType` + `import './style.scss'` |
| `edit.js` | Editor UI + `import './editor.scss'` |
| `save.js` | Static save output |
| `render.php` | Dynamic block SSR (optional) |
| `view.js` | Frontend-only JS (optional) |

## Step 4: Build

```bash
cd {target}/{plugin-slug}
npm install
npm run build    # dev: npm run start
```

## Step 5: Verify

Confirm these exist after build:

- `build/blocks-manifest.php`
- `build/format-types.js` + `build/format-types.asset.php`
- `build/{plugin-slug}/{block-slug}/` with `index.js`, `index.css`, `style-index.css`

Run `npm run lint:scss` if SCSS was edited.

## Architecture (Key Points)

### Multi-block auto-loading

- Blocks live in `src/{plugin-slug}/{block-name}/` (one folder = one block)
- `npm run build --blocks-manifest` generates `build/blocks-manifest.php`
- `{plugin-slug}.php` calls `wp_register_block_types_from_metadata_collection()` — **no PHP changes when adding blocks**

### format-types

- One file per format in `src/format-types/` (see `sample-format.js`)
- Register via `registerFormatType()` in each file
- Import all formats in `src/format-types/index.js`
- Built as separate webpack entry → enqueued in `{plugin-slug}.php`

### Build diff cleanup

`scripts/restore-unchanged-builds.sh` (postbuild) restores unchanged block build outputs from git HEAD.

## Adding More Blocks Later

**To an existing plugin** (no PHP changes):

```bash
cd src/{plugin-slug}
npx @wordpress/create-block@latest {new-block} --no-plugin
cd ../..
npm run build
```

Or copy an existing block folder and update `block.json`.

**To scaffold a brand-new plugin:** run Step 2 again with a new slug.

## PHP Docblock Warning

Never write glob patterns like `src/my-blocks/*/` inside PHP `/** */` comments — `*/` closes the comment early. Use plain language instead.
